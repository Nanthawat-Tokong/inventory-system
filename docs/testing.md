## 1. Integration test (Jest)

- ทุกไฟล์สร้างฐานข้อมูลทดสอบใหม่ (`inventory_db_test`) จาก `schema.sql` + ข้อมูลตั้งต้นชุดเดียวกัน → **ไม่แตะข้อมูลจริง** และผลทดสอบซ้ำได้ทุกครั้ง
- เปิด backend จริงที่ port 5099 แล้วยิง HTTP เหมือนหน้าเว็บ — ทดสอบตั้งแต่ route, สิทธิ์, logic จนถึงฐานข้อมูล
- ไฟล์อยู่ที่ `inventory-system/backend/tests/`

| ไฟล์ | จำนวน | ครอบคลุม |
|---|---:|---|
| `01_auth_users` | 18 | ล็อกอิน, token, สิทธิ์อัปเดตทันที, จัดการผู้ใช้ (ข้อมูลไม่ครบ, อีเมลซ้ำ, รหัสสั้น, ห้ามลบตัวเอง/admin คนสุดท้าย/คนที่มีประวัติ) |
| `02_master_data` | 29 | สินค้า, สาขา, ย้ายคลังหลัก, สินค้าประจำสาขา, **เกณฑ์แจ้งเตือนเฉพาะสาขามีผลทุกหน้า** |
| `03_inventory` | 20 | รับเข้า/ออก, จำนวนผิด (ติดลบ/ทศนิยม/ข้อความ), **ทำพร้อมกันยอดไม่เพี้ยน**, สิทธิ์ดูสต๊อก/ประวัติ |
| `04_requisitions` | 26 | ขอเบิกต้องมีของ, การจองของ, ผู้อนุมัติ ≠ ผู้จัดส่ง, กดส่งซ้ำ, ตรวจรับ, ไทม์ไลน์ |
| `05_disputes` | 12 | ของชำรุด, ของชดเชย, ปิดเคสต้องตกลง 2 ฝ่าย, ข้อความ |
| `06_reports` | 16 | ตัวเลขทุกรายงานตรงกับสต๊อกจริง, **รายวัน/รายสัปดาห์/รายเดือน**, สิทธิ์ดูรายงาน, การเบิกรายคน |
| `07_account_cancel_defects` | 14 | เปลี่ยนรหัสผ่าน (บังคับเปลี่ยน), ยกเลิกหลังอนุมัติ, ของชำรุดตัดทิ้ง/ส่งคืน |
| **รวม** | **135** | |

ตัวอย่างความถูกต้องที่ตรวจ: ยอดคงเหลือในรายงานความเคลื่อนไหวต้องเท่ากับสต๊อกจริงทุกแถว, ยอดรวมทุกแบบ (รายวัน/สัปดาห์/เดือน) ต้องเท่ากัน, กดจัดส่งพร้อมกัน 3 ครั้งต้องตัดสต๊อกครั้งเดียว

### บั๊กที่ชุดทดสอบเจอและแก้แล้ว (ตัวอย่าง)
- รับเข้าพร้อมกันหลายคำสั่งแล้ว `stock_after` ซ้ำกัน (การล็อกยังเห็นข้อมูลเก่า) → ใช้ READ COMMITTED
- ลบผู้ใช้แล้วประวัติสต๊อกของผู้ใช้นั้นหายไปด้วย (CASCADE) → ห้ามลบผู้ใช้ที่มีประวัติ
- admin ลบบัญชีตัวเองได้ / ข้อมูลไม่ครบทำให้ server error 500 / ค่าติดลบผ่านได้
- เกณฑ์แจ้งเตือนเฉพาะสาขาบันทึกได้แต่ไม่มีผล
- ติดตั้งใหม่จาก schema + seed ได้คลังหลัก 2 แห่ง

## 2. ทดสอบผู้ใช้พร้อมกัน
จำลองผู้ใช้ 10 คน (พนักงานสาขา 6, ผู้อนุมัติ 2, พนักงานจัดส่ง 1, admin 1) ทำงานจริงต่อเนื่อง 60 วินาที แล้วตรวจว่าสต๊อกไม่ติดลบและยอดถูกทุกรายการ
ปรับได้: `USERS=20 DURATION=30 npm run test:load` · ผล: [load-test-result.md](load-test-result.md)

ข้อจำกัด: ทดสอบบนเครื่องเดียวกับฐานข้อมูล ด้วยสินค้า 5 รายการ — ข้อมูลจริง 2,004 สินค้า × 4 สาขา โหลดหน้าแรก (สต๊อก 8,000 แถว) วัดได้ ~170 ms

## 3. ทดสอบหน้าเว็บ (Smoke)
`npm run smoke` ล็อกอินทีละบทบาทแล้วเปิดทุกหน้าด้วย Chrome แบบไม่มีหน้าต่าง ตรวจว่าไม่มี JavaScript error และหน้ามีเนื้อหา
ต้องรัน backend และ `npm run dev` ไว้ก่อน · บัญชีที่ยังต้องเปลี่ยนรหัสผ่านจะถูกพาไปหน้าบัญชี — ใช้บัญชีที่เปลี่ยนรหัสแล้ว หรือรันกับฐานข้อมูลทดสอบ

## 4. Postman
Import `docs/postman_collection.json` → ตั้งตัวแปร `baseUrl` (ค่าเริ่มต้น `http://localhost:5000/api`), `email`, `password` → รัน **Login** ก่อน (token ถูกเก็บอัตโนมัติ) แล้วรันคำขออื่นได้เลย

## 5. UAT
ใช้ [uat-questionnaire.md](uat-questionnaire.md): ให้ผู้ใช้แต่ละบทบาททำงานตามสถานการณ์ แล้วให้คะแนน 1–5 — เกณฑ์ผ่านเฉลี่ย ≥ 4.0
